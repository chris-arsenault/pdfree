# Public encrypted PDF fixtures

These synthetic PDFs were generated by qpdf on 2026-10-08 from `formFixture`
using the independent suite in `src/core/encryptedImport.security.test.ts`.
They contain public sample text and fields, with no user documents or credentials.
They are test inputs and are excluded from production bundles.

| Prefix   | Encryption                |
| -------- | ------------------------- |
| `R2`     | 40-bit RC4                |
| `R3`     | 128-bit RC4               |
| `R4-RC4` | RC4 with crypt filters    |
| `R4-AES` | AES-128                   |
| `R5`     | Legacy AES-256 revision 5 |
| `R6`     | AES-256 revision 6        |

`empty` files have an empty opening password. `password` files use opening
`reader-fixture` and owner `owner-fixture`. `unicode` files use opening
`Montréal-€` and owner `maître-£` for revisions 2–4; revisions 5–6 use opening
`Montréal-東京` and owner `maître-🔒`. These values are public fixture passwords.

The native suite regenerates equivalent inputs under ignored `test-results/`,
opens them using both credentials and independently checks edited outputs.
After an intentional fixture update, copy the generated inputs here as whole
files. Unit tests use these fixtures without requiring qpdf at runtime.

`pubsec-40.pdf`, `pubsec-128.pdf`, `pubsec-AES128.pdf` and `pubsec-256.pdf`
were generated independently with Apache PDFBox 3.0.6. The native suite uses
`tooling/RecipientFixtures.java` to regenerate multiple-recipient PDFs and
`tooling/ReadRecipient.java` to decrypt exports independently. `recipient.crt`
and `other.crt` are public synthetic RSA certificates; matching `recipient.p12`
and `other.p12` include test-only private keys and use password `identity-fixture`.
Regenerate/copy the PDFs and identities as a matching set. Never use these keys
for real documents, and never replace them with a user's identity or PDF.
